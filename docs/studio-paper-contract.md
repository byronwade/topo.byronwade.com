# Studio Paper contract

The Paper file named `Topo` is the visual source for the default Studio. The executable, React-independent board inventory is `packages/studio-api/src/boards.ts`; its tests require exactly 23 uniquely identified, directly addressable boards and the exact shared frame. `apps/studio/src/design/boards.ts` is a compatibility re-export for Studio-local location types. Default landing paths and shell behavior live in the composed registry at `apps/studio/src/studio-config.tsx`. This document explains the contract without making Paper access a requirement for contributors or agents.

## Hybrid canvas contract

Components opens on the Paper composition: a compact coverage rail, the selected component's exact evidence, and its preview-readiness inspector. Explicit preview sources open the exact source-ordered or `preview=<stable-id>` variant in the rounded media well, using the newest matching captured artifact or an explicit failed, unavailable, or uncaptured state. Variant selection is reload-safe and never substitutes pixels for component or preview identity. Components without a preview source remain coverage gaps and resolve a consuming application screen only through canonical `usedBy` identities, rendered through the same live iframe, newest snapshot, or explicit missing-evidence stage as Editor. **Map** switches to the complete source-domain topology without changing the selected component or variant; **Preview** returns to its exact evidence. The map remains directly addressable with `?canvas=map`, uses stable centered landscape rows derived from measured source-group area, and exposes exact scene dimensions and aspect as DOM telemetry for the executable board contract.

Flows preserves Paper's selected-plus-supporting composition at normal zoom. **Fit Atlas** reveals every explicit flow lane in stable, centered landscape rows; the nearest rendered lane supplies supporting context, while the canvas exposes exact lane count, focus count, dimensions, and aspect for the executable board contract.

Interaction Probe preserves Paper's 1100px evidence stage and 340px inspector. The inspector's 38px target well remains in place as a labeled native selector over every canonical probe on the selected route. Selecting a target keeps the route context, updates the effect and verdict evidence in place, and writes `probe=<stable-id>` to the ordinary Studio query-selection seam. A direct link or reload restores that exact observation and its owning screen; an absent or stale identity falls back deterministically without creating a second interaction store.

The center Editor, coverage-gap Components Preview, Doctor Findings, Notes Detail, and all Atlas topology viewports are real PixiJS surfaces clipped by the shared Open Design canvas shell. Captured component variants use an exact artifact image inside the same rounded shell rather than reconstructing application markup. The center pane itself has no outline; its working viewport is inset 14px on each side, 4px below the 40px canvas titlebar, and 14px above the workspace edge, uses a 16px radius, and clips every GPU and DOM overlay to that shape. The only full-shell rule is the dark divider below the 52px application header. Editor, coverage-gap Components Preview, Doctor Findings, and Notes Detail share one 780 × 706 evidence artboard at the 1440 × 900 reference size and retain Paper's 16px radius, `#23252E` border, and deep elevation. Captured component variants instead occupy a bounded 720 × 420 media frame with exact dimensions, adapter, capture time, and preview identity. Both surfaces are evidence-only: they promote a selected real application iframe where appropriate or show accepted capture evidence and never become a second source of application markup. Editor exposes the selected route, source, components, findings, notes, and capture metadata. Its 248px navigator searches every discovered default screen rather than slicing the project inventory, and its Assets state searches every normalized component. The 416px former insertion surface remains a bounded eight-card searchable component-preview catalog; exact visible, matching, and total counts disclose that presentation limit, and the overflow action navigates to the complete Atlas catalog instead of editing source. Compact relationship lists in the evidence tree and inspector likewise state their complete counts and link to their owning destination. Finding actions select the clicked canonical identity before opening Doctor. Doctor Findings retains Paper's route / canvas / findings composition, but its compact navigator shows canonical paths in shared hierarchy order rather than indistinguishable `page.tsx` filenames. Each selected finding opens its exact source-backed screen through screen source identity or component `usedBy`; no pin is drawn unless canonical evidence eventually supplies an actual screen coordinate. Notes Detail uses the same route navigator and stage. Its inspector opens with compact source, note, and anchor evidence plus previous/next navigation; the title/body editor and destructive control appear only after Edit, and Cancel restores the accepted record. It renders a note anchor only from recorded normalized coordinates and labels a manually chosen-but-not-yet-attached route as a candidate until Re-anchor persists the relationship. Element and region placement temporarily adds a note-purple dashed interaction field inside the artboard, a compact instruction pill, and a live point or rectangle preview; it captures the gesture without changing the rounded canvas shell or making Pixi authoritative. While an element inspection is pending, the field exposes that state and blocks a second gesture. A signed live iframe may return current semantic evidence for the selected point; snapshot and missing-bridge modes remain explicitly coordinate-only. The Notes index retains the Paper two-pane geometry and adds one compact search control that composes with the selected lifecycle or anchor facet. Atlas Routes opens on the selected 780 × 688 full-screen evidence composition shown by Paper. **Map** exposes the compact overview of named route areas and unique route families at `?canvas=map`, with the selected region top-aligned so adjacent territory remains visible rather than leaving a dead upper field; **Screen** returns to the query-free evidence presentation without losing selection. Components Preview uses the compact Paper coverage sections. Exact preview sources resolve to matching artifact records; source-less coverage gaps resolve to a consuming screen without inferring relationships from names or copy. Components Map retains the complete searchable, collapsible source-domain catalog, reveals new selections, and presents the same group order, preview status, membership, and selected identity as the versioned topology scene. Flows retains Paper's two-lane focus composition at normal zoom while Fit Atlas exposes every lane and explicit branch.

Visual fidelity does not remove semantic form structure. Command, catalog, and component searches; flow and note authoring; and Settings selectors retain the approved compact appearance while using native label associations and stable names. Muted captions remain visually subordinate without dropping below `4.5:1`, and error text uses theme-specific values against its real surfaces. The board verifier checks every visible form control, orphaned label, and semantic contrast pair across all 23 boards so placeholder-only fields or illegible token drift cannot silently return.

`@topo/canvas-engine` owns the serializable camera transform and pure zoom, pan, fit, wrapping, viewport selection, visibility-delta, route-section, route-district, route-family, and component-group functions. One route organizer drives the route sidebar and renderer-neutral scene: entry groups lead, route families remain adjacent, static siblings precede dynamic siblings, and each family retains its exact screen states, sources, primary screen, dynamic status, render-status counts, nearest present parent, ordered children, and hierarchy level. Oversized automatic domains split into stable nested districts only when at least three child prefixes contain two or more route families; singleton routes remain with the parent, while configured groups remain untouched. Those exact districts then compose into stable regions: one for each substantive automatic root, one **Top level** region for remaining automatic roots, and an independent region for each configured district. Scene schema version 4 adds exact section membership, provenance, geometry, aggregate counts, and selected-section bounds to the grid-or-hierarchy district and explicit parent-child connection contract in the compact `routeMap`. A separate pure component organizer recognizes common source domains, applies optional longest-prefix `atlas.componentGroups` ownership, and returns exact membership plus coverage aggregates without geometry. Component scene schema version 2 packs those groups into stable bounded rows and exposes both selected-component and selected-group bounds. Studio, daemon, MCP, and context schema version 7 consume that same result, including the distinct recorded-flow and source-inferred-journey rails. `@topo/react` applies the same pointer, touch, wheel, pinch, toolbar, and keyboard behavior to every surface. Select mode reserves primary mouse and pen input for entity selection, Pan mode uses it for camera movement, and middle mouse or touch can always move the camera. The public Studio runtime exposes the current mode and Fit action. The Pixi layers draw the grid, rounded region fields, named route areas, hierarchy trunks, semantic route cards, status evidence, directed navigation connections, selected screens, component and flow nodes, and capture textures; only overscanned viewport intersections remain render-visible, and Pixi mutations occur only when identity enters or exits that set. Map mode hydrates at most 24 visible primary-screen thumbnails through the shared cache, while Screen mode retains the selected full-size texture. Map and Screen controls switch presentation without changing graph identity. Live application content and inspector controls remain synchronized DOM overlays in Screen mode. `@topo/live-frame-host` admits at most four live frames by default: selected first, hover second, then nearby screens already marked live. The selected and hovered frames are interactive, while nearby frames are click-through and cannot steal canvas input. Actual Pixi nodes stop pointer propagation so selection wins, while empty canvas presses reach the shared pan controller. Captured route metadata comes from `/snapshots`; captured component metadata comes from `/component-previews`. Extension-bearing `/image.png` endpoints supply root-contained bytes. All texture surfaces use the same four-request hydration budget, prioritize selected or nearest visible identities, and keep a semantic fallback on failure. This split preserves GPU scale, accessibility, inspection, interaction, and deterministic reads for LLM clients.

At the reference viewport, the checked renderer viewport is `(262, 96, 900 × 760)`. Shared evidence workspaces fit the 780 × 706 artboard inside that bounded viewport. Atlas Routes fits the selected 780 × 688 screen on first load. Its addressable map frames the selected region with deterministic start alignment on the vertical axis so its surrounding product structure is immediately legible and the next region can remain visible; a reload with `canvas=map` retains that presentation. The explicit Area, Region, and Atlas controls fit the selected route district, containing region, or complete regional map, and the zoom-percentage control returns to the active semantic focus. Selecting a route card or sidebar family updates the shared Studio selection, reveals that family in the navigator, switches to Screen, removes only the map-presentation query, and fits its full evidence view. The explicit Map control returns without losing selection. Route-usage nodes on the component map open the corresponding route, while Preview restores the selected component's exact preview variant or its explicit route-consumer fallback. Captured component variants occupy the component media well and retain their stable preview ID in the Studio address. Resolved flow steps reuse route snapshots by stable screen identity; unresolved steps remain semantic cards. Flow steps update the inspector without losing camera state, while empty-canvas drag remains available. Each route canvas exposes stable renderer, camera, presentation mode, active map focus, route-map dimensions and aspect, total and visible section, group, route/screen, and connection counts, culled count, available texture count, loaded texture count, and texture error count attributes for browser verification. The daemon and MCP expose all three versioned scene structures and artifact metadata directly.

## Behavior boundary

Studio reads graph, flow, note, finding, snapshot, and component-preview records from the loopback daemon. It subscribes to graph events and calls daemon actions for scan, route capture, component capture, diagnostics, note creation, and review export. The 416 × 224 default annotation palette matches Paper's 14px-radius `#1B1B1F` surface, exact two four-choice rows, and tokenized type hierarchy. Selecting a preset opens a transient composer that shows the exact selected screen, flow step, flow, or absence of a durable target before it writes. The visual Flow marker choice remains a target-free canonical `flow` note; no eighth note type or hidden relationship is introduced. If the daemon is absent, Studio renders deterministic demo records and labels the footer `Demo data · daemon offline`; this keeps all 23 states inspectable without presenting fixture data as live workspace evidence. The Fieldbase fixture contains 128 distinct application component names across ten source domains and 11 distinct notes, so the public demo never substitutes numbered filler for the same identities shown by canvas, search, inspectors, exports, or agent-readable records.

Settings preserves Paper's destination geometry while enforcing real authority. General displays the package-derived project name and daemon source root as read-only evidence, and the About board reads version and distribution from `docs/product.json` with working repository, docs, issue, license, and release links. Capture displays the sanitized `topo.config.ts` auto-capture, viewport, and headless policy; only live-frame capacity and hover promotion are editable browser preferences. The capacity selector is bounded to one through eight and immediately feeds the hybrid iframe pool. The Playwright diagnostics toggle controls whether a Doctor rerun follows its environment report with the explicit runtime-probe endpoint. No setting claims to mutate project configuration when it only writes browser storage.

Every durable product entity remains LLM-readable outside the UI. Graph and diagnostic records are versioned JSON, flows are JSON, notes are Markdown with frontmatter including normalized point or region anchors, preview artifacts have explicit metadata records and stable binary resource URIs, review export is Markdown, and the daemon exposes the canonical context manifest and bounded context queries. The Studio board contract itself remains a typed array with stable names, paths, roles, and summaries.

The 23 boards are the shipped default contract, not a closed destination union. Source builds may compose additional destinations and commands or remove defaults through the [Studio extension API](./STUDIO_EXTENSIONS.md). Such extensions do not mutate this default Paper ledger. `studioBoards`, `studioFrame`, and `findStudioBoard()` are public from `@topo/studio-api`, so an extension, verifier, or agent can inspect the defaults without importing React or duplicating routes.

## Change rule

Any Paper board addition, rename, removal, or destination change must update all of the following in one change:

1. `packages/studio-api/src/boards.ts` and its focused test;
2. `apps/studio/src/design/boards.ts` only if the compatibility surface changes;
3. this board inventory and any affected behavior description;
4. `docs/product.json` evidence or canonical documentation when feature behavior changes;
5. the append-only product change record through `pnpm docs:record`.

`pnpm verify:studio-boards` builds the production Studio, opens every board in Chromium at 1440 × 900, and writes `studio-board-report.json` plus one screenshot per board. A pass requires direct route identity, the board's ready selector, zero browser or visible Studio errors, exact root/chrome/pane geometry, borderless structural panes and rounded renderer viewport, the single theme-correct header divider, the declared dark or light theme, and exactly one healthy Pixi canvas only where the board contract requests one. The Notes detail check additionally enters coordinate-only point placement, clicks a deterministic artboard position, and verifies the resulting attached normalized anchor before recording a placement screenshot. `pnpm verify:studio-profiles` separately proves the signed live-frame semantic bridge across two isolated profile origins. The reports are machine-readable acceptance evidence; screenshots remain the human visual comparison surface against Paper.
